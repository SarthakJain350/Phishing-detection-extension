## 1. Dataset Structure and Statistics

### 1.1 File Overview
- **Path:** `data/raw/url_benign_malicious_file.csv`
- **File Size:** 640,557,725 bytes (~610.88 MB)
- **Line Count:** 1,000,001 lines (1 header line + 1,000,000 data rows)
- **Total Columns:** **547** columns

### 1.2 Column Layout & Lexical Features
1. **`url`** (Column 0): Raw URL string.
2. **`target`** (Column 1): Binary integer label represented as text (`0` or `1`).
3. **`COL1` through `COL545`** (Columns 2–546): Lexical token decomposition of the URL string:
   - For example, `https://www.amazon.com/...` produces:
     - `COL1` = `'https'`
     - `COL2` = `'://'`
     - `COL3` = `'www'`
     - `COL4` = `'.'`
     - `COL5` = `'amazon'`
     - `COL6` = `'.'`
     - `COL7` = `'com'`
     - `COL8` = `'/'`
   - These 545 extra columns are sparse pre-tokenized features generated by CIC for lexical/transformer ML models.
   - For our heuristic detection engine, all `COL1`–`COL545` columns are redundant; only `url` and `target` are relevant.

### 1.3 Data Integrity Statistics Across Full 1,000,000 Rows
- **Null URLs:** 0
- **Empty / Whitespace URLs:** 0
- **Null Targets:** 0
- **Invalid / Non-Binary Targets:** 0 (every row contains strictly `'0'` or `'1'`)
- **Scheme-less URLs:** **601,778** (60.18% of URLs begin without `http://` or `https://`, e.g. bare domains like `answers.com/topic/...` or `zeimela.org/...`)
- **URLs with binary/control characters:** **92 rows** (contain ASCII control bytes < 32)
- **Truncated-looking URLs (ending with `=`)**: **11,173 rows** (due to base64 parameters or quoted-printable cutoffs)
- **Very short URLs (< 5 characters):** **24 rows** (e.g. stray fragments like `¾5092`)
- **URLs without a resolvable hostname:** **929 rows** (after prepending `https://`, URL parser cannot extract a valid hostname)

## 2. Target Distribution & Label Semantics

### 2.1 Distribution (Verified Fact)
- **Target `0`:** **429,964 rows** (42.996%)
- **Target `1`:** **570,036 rows** (57.004%)
- **Total:** **1,000,000 rows**

### 2.2 Empirical Observations on Label Semantics
> [!IMPORTANT]
> **Documentation Note:** The local `data/raw/readme_source.txt` file explicitly documents the *Multi-Format Attachment Dataset* (Word, Excel, PDF, HTML, QR archives) and its feature extraction notebooks. It does **not** document `url_benign_malicious_file.csv`. Therefore, `readme_source.txt` cannot be used as official verification for the URL CSV's label semantics.

In the absence of a URL-dataset-specific schema README, label semantics must be treated as an **empirical observation based on sampling**:
- **Target `0` (Observed as Benign):**
  - Sampling across target `0` rows shows legitimate academic, institutional, and open-source websites:
    - Mailing lists: `lists.sourceforge.net`, `lists.freshrpms.net`, `xent.com/mailman/`
    - Content portals: `answers.com/topic/...`, `smh.com.au`, `thinkgeek.com`, `linux.ie`
- **Target `1` (Observed as Malicious / Threat):**
  - Sampling across target `1` rows shows credential harvesting pages, lookalike domains, known phishing kits, and malware distribution points:
    - Phishing kits: `mx1.corrierefranco.it/images/login/secure.bankofamerica.com/signOnScreen.go/sign-in/`
    - Suspicious redirects: `id-redirection.cu.cc`, `zeimela.org/amcntrlde/webscr_prim.php?`
    - Free hosting abuse: hundreds of `000webhostapp.com`, `firebaseapp.com`, `glitch.me` lures.

**Status:** The mapping of `0 = benign` and `1 = malicious` is consistent with all observed data samples, but remains an **inferred/observed mapping** rather than an officially documented specification for this specific CSV.

## 3. Threat Specificity: Observed Heterogeneity and Noise

### 3.1 Observed Malware Payload Drops & C2 Botnet URLs
Direct inspection across the 570,036 `target = 1` rows reveals that the malicious class includes threat categories beyond social engineering or phishing:
- Rows ~150,000–150,050 consist of raw IP and non-standard port malware download links:
  - `http://103.13.221.93:8082/02.08.2022.exe`
  - `http://154.9.253.10:8090/02.08.2022.exe`
  - `http://117.205.58.66:33357/Mozi.m` (Mozi IoT botnet binary)
  - `http://123.60.186.33:7777/02.08.2022.exe`
- These samples reflect commodity malware droppers, payload hosting, and botnet propagation typically aggregated by threat feeds like URLhaus or MalwareBazaar, rather than web phishing lures designed to deceive human users.

### 3.2 Observed Noisy / Legitimate URLs Marked as Target 1
Direct inspection of rows 1–25 reveals standard benign service and infrastructure URLs assigned `target = 1`:
- `https://www.amazon.com/ref=pe_175190_21431760_M3T1_SC_g_i`
- `http://g-ecx.images-amazon.com/images/G/01/x-locale/cs/te/logo.png`
- `http://www.w3.org/TR/html4/loose.dtd`
- `http://twitter.com/share?...`
- `http://www.facebook.com/sharer.php?...`

*Observed Implication:* While the authors' exact scraping script is not provided, this pattern commonly occurs when all hyperlinks are extracted indiscriminately from phishing email templates (such as legitimate logo links, schema DTDs, or social share widgets). Evaluated against ground truth `target = 1`, these records represent noisy labels that would distort phishing evaluation metrics.

### 3.3 Observed Benign Class Characteristics (`target = 0`)
- High concentration of mailing list links (`lists.sourceforge.net`, `freshrpms.net`, `answers.com`).
- 60%+ scheme-less URLs that require normalisation before analysis.

- **Title:** *CIC-Trap4Phish: A Unified Multi-Format Dataset for Phishing and Quishing Attachment Detection*
- **Publication:** arXiv preprint (arXiv:2602.09015), Canadian Institute for Cybersecurity (CIC), University of New Brunswick (UNB), February 2026.
- **Landing Page:** `https://www.unb.ca/cic/datasets/trap4phish2025.html`

### 4.2 Published Count vs. Downloaded CSV Count Discrepancy
- **Landing Page Published Table:**
  - Benign URL strings: **433,918**
  - Malicious URL strings: **614,656**
  - Total advertised: **1,048,574** (or $2^{20} = 1,048,576$)
- **Downloaded File (`url_benign_malicious_file.csv`):**
  - Target `0`: **429,964** (difference of -3,954 compared to published benign)
  - Target `1`: **570,036** (difference of -44,620 compared to published malicious)
  - Total in CSV: **1,000,000** exactly
- **Status: UNRESOLVED QUESTION.**
  - There is no primary documentation or release note in the download archive explaining why the CSV contains exactly 1,000,000 rows instead of the published 1,048,574.
  - While it is plausible that the file was capped or subsampled for public download, this is an inference and cannot be confirmed without primary documentation from the authors.

### 4.3 Licensing & Usage Restrictions
- **Attachment Dataset Documentation:** `readme_source.txt` states:
  - *"This dataset is released under the Creative Commons Attribution–NonCommercial 4.0 (CC BY-NC 4.0) license."*
  - *"Redistribution or modification is allowed for academic and research purposes only. Commercial use is prohibited without written permission."*
- **URL CSV Licence Status: UNRESOLVED QUESTION.**
  - The UNB landing page and download form require institutional registration and specify academic research use.
  - However, neither the download page nor the CSV header explicitly confirms whether the CC BY-NC 4.0 licence applies to `url_benign_malicious_file.csv` as an independent artifact.
- **Redistribution Boundary:** Regardless of the specific open licence, raw or derived subsets of this dataset must not be committed to a public Git repository or bundled into commercial binaries without explicit confirmation from UNB.

## 5. Compatibility Assessment with Current Evaluation Pipeline

### 5.1 Critical Adapter Defect (Column Name Mismatch)
In `evaluation/prepare_dataset.py`, lines 289–290 currently state:
```python
raw_url = row.get("url")
raw_label = row.get("label")  # <--- DEFECT
```
- The actual downloaded CSV contains columns `url` and **`target`** (not `label`).
- As a consequence, running `prepare_dataset.py` against `data/raw/url_benign_malicious_file.csv` silently skips **100% of rows** (`raw_label is None`), yielding 0 samples!
- The adapter requires updating to check `row.get("target")` (or fall back to `row.get("label")`).

### 5.2 Header and Memory Constraints
- Reading all 547 columns into a standard pandas DataFrame consumes ~1.8 GB of RAM and is slow.
- The evaluation pipeline only needs `url` and `target`. An adapter reading only `usecols=["url", "target"]` or using Python's `csv.DictReader` with selective extraction operates in constant memory (< 20 MB).

### 5.3 URL Normalization & Scheme Prepending
- 60.18% of rows in `url_benign_malicious_file.csv` lack a scheme (`://`).
- The existing `normalize_url_for_eval()` helper prepends `https://` if `"://"` is absent, which allows these scheme-less URLs to be parsed cleanly.
- The hostname validation check (`parsed.hostname`, dot requirement, consecutive dot rejection) successfully filters out the ~929 malformed and 92 control-byte rows.

## 6. Risks, Limitations and Evaluation Impact

1. **Threat Conflation (Malware vs Phishing):**
   - The detector was designed primarily to flag fraudulent brand impersonation, deceptive homoglyphs, credential harvesting forms, and social engineering paths.
   - Raw IP malware downloads (e.g. `http://103.13.221.93:8082/02.08.2022.exe`) trigger IP-hostname heuristics, but botnet endpoints with random strings will register false negatives under a phishing detector if evaluated as "phishing".
2. **Scraped Email Noise (False Positives on Real Brands):**
   - As observed in Section 3.2, legitimate domains like `amazon.com`, `facebook.com`, and `w3.org` appear under `target = 1`. If evaluated against ground truth `target = 1`, our detector will correctly classify them as legitimate and be penalised as false negatives, or if flagged, could distort heuristic metrics.
3. **Heavy Imbalance in Benign Topologies:**
   - Over 40% of the benign set consists of mailing lists and forum links (`mailman`, `sourceforge`, `answers.com`), which is less representative of standard enterprise web navigation than lists like Tranco Top Sites.

---

## 7. Final Classification & Recommendation

### Conclusion: **Do NOT include in primary phishing ground-truth benchmark**

**Detailed Rationale:**
- The dataset is **not pure phishing ground truth**. Observed samples demonstrate a mixed threat feed containing malware payload downloads, botnet traffic, and noisy artifacts scraped from email attachments alongside phishing lures.
- **Licensing and provenance documentation** for the URL-only CSV contains unresolved questions regarding exact source breakdown and formal licence terms.
- **Candidate Benchmark Recommendation:**
  - **Primary Phishing Benchmark:** Maintain the cleaner, verified candidate combination of **PhishTank** (verified community/analyst phishing) + **Tranco Top Sites** (verified legitimate domains).
  - **Broader Research Use Only:** If CIC-Trap4Phish is used at all in future phases, it should be restricted to secondary evaluations of broader malicious-URL detection, with raw payload downloads explicitly tagged as `"malware_url"`.
